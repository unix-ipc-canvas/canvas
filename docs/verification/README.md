# 테스트 명세 — 다중 그림판 공유 캔버스 서버

[문서 안내](../../README.md#관련-문서)

`make test`(`scripts/verify.sh`)가 아래 항목을 이 번호로 실행하고 PASS·FAIL·SKIP을 출력한다. 각 항목의 괄호는 확인하는 요구사항이다. 문서 검사(T-00)가 요구사항 번호가 모두 여기에 대응되는지, 이 표와 `verify.sh`의 번호가 같은지 확인한다. 실행 명령은 [README의 테스트](../../README.md#테스트)에 있다.

- SKIP은 검증 완료가 아니다. 실행 파일이 없거나, 그 환경에서 돌릴 수 없는 항목(예: ThreadSanitizer를 쓸 수 없는 커널)만 SKIP이다.
- 우리 서버가 떠 있지 않을 때 돌린다. 모든 항목이 끝나면 남은 자원을 검사한다(T-20).

## 빌드와 구조

| 번호 | 항목 | 판정 기준 |
| --- | --- | --- |
| T-00 | 문서 검사 (C-10) | 문서의 링크와 앵커가 살아 있다. 요구사항 번호가 모두 이 문서에 나온다. 이 표와 `verify.sh`의 번호가 같다. 성능 예측이 `작성 완료` 상태다 |
| T-01 | 경고 없는 전체 빌드 (C-1, C-4) | `make EXTRA_CFLAGS=-Werror`가 성공한다 |
| T-02 | 버전별 빌드 (C-4, C-7) | `make pipe`, `make mq`, `make shm`, `make upipe`가 각각 성공한다 |
| T-03 | 공통 코드에 IPC 고유 호출 없음 (C-7) | `src/common`, `src/bench`, `src/test`에 `msgget`, `shmat`, `semop`, `mkfifo` 등이 없다 |
| T-04 | 전송 계층 시험 | `scripts/test-transport.sh`가 세 IPC 모두 통과한다(1단계 시험) |
| T-05 | 1단계 벤치마크 내용 검사 | `bench_<ipc> -V`가 모든 응답의 내용을 확인하고 성공한다 |

## 2단계 응용

세 버전 각각에서 실행한다.

| 번호 | 항목 | 판정 기준 |
| --- | --- | --- |
| T-10 | 기본 동작 (F-1, F-2, F-5, F-9, F-11, N-3, C-3) | 서버(그림판 2개)와 부하 클라이언트 4개를 함께 돌리면 모든 클라이언트가 종료 코드 0, 서버의 그림판별 체크섬이 검증기 정답과 같다 |
| T-11 | 락 방식과 동시 요청 (F-2, N-3, C-9) | `-l rw`, `mutex`, `room` 각각에서 클라이언트 8개 × 동시 요청 16 × DRAW 100%의 체크섬이 정답과 같다 |
| T-12 | SNAPSHOT 내용 (F-3) | 알려진 DRAW를 보낸 뒤 그 영역의 SNAPSHOT이 기대한 값과 바이트마다 같다. 그림판이 다르면 섞이지 않는다 |
| T-13 | 잘못된 요청 (F-6) | 방 번호 초과, 영역 밖, 크기 0, SNAPSHOT 한 변 257, 알 수 없는 종류에 `RESP_ERROR`가 오고 그림판 체크섬이 바뀌지 않는다 |
| T-14 | STATS (F-4) | DRAW·SNAPSHOT 건수가 보낸 수와 같고, 접속 수·그림판 수·워커 수가 맞다 |
| T-15 | 서버 시각 (F-7) | 클라이언트의 응답 검사(t0 ≤ t_recv ≤ t_deq ≤ t_lock ≤ t_send ≤ t5)가 모든 응답에서 통과한다 |
| T-16 | 서버 종료 (F-8) | SIGINT를 받으면 그림판별 체크섬을 출력하고 1,048,576B + 머리인 PGM을 저장하고 종료 코드 0. 멈춘 클라이언트가 있을 때 두 번째 신호를 보내면 2초 안에 끝나고 자원이 남지 않는다 |
| T-17 | 접속 거부 (F-5) | 서버가 없으면 클라이언트가 종료 코드 1로 끝난다. 같은 번호가 실행 중이면 두 번째 클라이언트가 거부된다 |
| T-18 | 스레드 수 (C-2) | 서버, 부하 클라이언트, 그리기 클라이언트, 실행기의 `/proc/<pid>/task`가 3개 이상이다 |
| T-19 | 그리기 클라이언트 (F-10) | 명령 줄 모드의 그리기 클라이언트 둘이 같은 그림판에서 서로 그린 것을 SNAPSHOT으로 보고, 다른 그림판에서는 보지 못한다 |
| T-22 | 서버 중복 실행 (N-4) | 서버가 떠 있을 때 두 번째 서버가 종료 코드 1로 끝나고 첫 서버의 자원을 건드리지 않는다 |
| T-23 | 규모 (N-1, F-12) | 실행기로 클라이언트 1024개 × 그림판 8개를 짧게 돌리면 모두 종료 코드 0이고 그림판별 체크섬이 정답과 같다 |
| T-24 | 경쟁 시연 (N-3) | 락을 끈 서버(`-l none`)에서는 같은 칸을 많이 겹쳐 그린 체크섬이 정답과 어긋난다. 락이 경쟁 상태를 실제로 막고 있다는 대조군이다 |
| T-25 | ThreadSanitizer (N-3) | `-fsanitize=thread`로 빌드한 서버·클라이언트로 T-10을 줄여 돌리면 보고가 0건이다. TSan을 쓸 수 없는 환경이면 SKIP |
