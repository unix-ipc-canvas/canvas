## 2. AI가 틀렸던 사례 (최소 2개)

실제로 확인한 것만 적습니다. "확인 방법"에는 우리가 돌린 명령이나 측정 결과를 적습니다.

| 번호 | 날짜 | AI의 제안·설명 | 실제로 확인한 내용 | 확인 방법과 조치 |
| --- | --- | --- | --- | --- |
| 1 | 11/18 | 우리 System V key 60020~60029 를 16진수 `0xEA6x` 로 계산해, 남은 자원 검사가 `0x0000ea6` 으로 시작하는 key 를 찾게 짰다 | 60020 = `0xEA74` 이다. 우리 key 는 `0xEA74`~`0xEA7D` 이고 `0xEA6x` 는 60000~60015(다른 팀). 검사가 엉뚱한 key 를 봐서 남은 자원이 있어도 늘 통과했다 | 측정 스크립트에 같은 검사를 넣다가 의심. shm 서버를 띄운 채 `ipcs -m -s` 로 실제 key `0x0000ea76`~`0x0000ea79` 를 확인했다. key 를 `verify.sh` 처럼 `printf '0x%08x' $((60000 + 팀번호 * 10 + y))` 로 계산하게 고치고 비정상 종료 검사를 다시 돌렸다(19/19 통과) |
| 2 | | | | |

AI가 한 말 중 우리 컴퓨터에서 직접 확인해 볼 것 (틀렸으면 위 표로 옮기기)

- [ ] System V 메시지 최대 크기 8192B, 큐 용량 16384B → `cat /proc/sys/kernel/msgmax /proc/sys/kernel/msgmnb`
- [ ] 파이프 버퍼 기본 64KB, PIPE_BUF 4096B → `fcntl(fd, F_GETPIPE_SZ)`, `getconf PIPE_BUF /`
- [ ] "작은 메시지에서는 shared memory가 pipe보다 빠르지 않을 수 있다" → 1단계 64B 측정
- [ ] "mq로 1MB를 보내면 조각마다 송수신이 교대한다" → 1단계 1MB 측정의 자발적 컨텍스트 스위치 수
- [ ] AI가 설계 문서에 적은 그 밖의 숫자와 예상 전부

지금까지 확인된 것

- 11/12 이동건 PC(Ubuntu, 커널 7.0.0)에서 `msgmax` 8192, `msgmnb` 16384, `PIPE_BUF` 4096, `pipe-max-size` 1048576을 확인했다. AI의 설명과 같았다. 측정용 컴퓨터에서 다시 확인한다.
- 11/12 AI가 캔버스 저장 형식을 PPM이라고 적어 왔으나, 한 칸 1바이트 회색조는 PGM이 맞다. AI가 문서를 다시 쓰다가 스스로 고쳤다. 사례로 쓸지는 팀이 정한다.

| 11/16 | `src/transport/transport_pipe.c` | `true`, `false`를 쓰면서 `<stdbool.h>`를 넣지 않아 빌드 실패 | `make EXTRA_CFLAGS=-Werror` 컴파일 오류 | `#include <stdbool.h>` 추가 |
| 11/16 | `src/transport/transport_mq.c` | 교착 상태. 큰 응답을 받던 클라이언트가 죽으면 워커가 가득 찬 응답 큐의 `msgsnd`에서 영원히 기다리고, 살아 있는 클라이언트의 응답도 모두 막힌다. AI는 "보내는 도중에 죽는 경우는 드물다"며 처음 기다릴 때 한 번만 상대를 확인하게 짰다 | 임시 부하 검사에서 1MB 응답을 받던 클라이언트를 `kill -9` 하자 서버가 멈춤. `ipcs -q`로 두 큐가 가득 찬 것을 확인 | 잠금 파일을 200ms마다 보는 감시 스레드를 넣어 죽은 클라이언트의 조각을 큐에서 꺼내 버리고 워커를 EPIPE로 빠져나오게 함 |
| 11/18 | `src/bench/bench.c` | 섞임. 초안은 클라이언트마다 24B HELLO 를 먼저 보냈다. pipe 버전은 `PIPE_BUF` 이하 요청을 잠금 없이 쓰므로, 다른 클라이언트의 64KB 요청이 써지는 도중에 HELLO 가 끼어들어 요청 스트림이 깨졌다. #20 에서 A 가 알린 약속("한 실행 안에서 PIPE_BUF 이하·초과 요청을 섞지 않는다")을 어긴 것이다 | `-V`(모든 응답 내용 검사)로 pipe, 클라이언트 8개, 64KB 를 돌리자 "61416번째 바이트가 다름". 61416 = 61440 - 24 로, 4KB 경계에 HELLO 머리(24B)가 끼어든 위치였다. 동시 요청 1, 클라이언트 2개에서도 재현됐다 | HELLO 도 측정 메시지와 같은 크기로 보내게 고침. pipe·mq·shm 각각 크기 0B~1MB, 클라이언트 1·2·8개, 동시 요청 1·16 조합을 `-V` 로 돌려 불일치 0 |
